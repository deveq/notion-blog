## 1. 핵심 정보

- **목적**: Notion 데이터베이스에 작성한 글을 웹사이트에서 최신순 피드 형태로 보여준다. 글 작성은 Notion에서만 하고, 웹에서는 읽기만 한다.
- **사이트 이름**: notion-blog
- **소개 문구**: notion blog toy project with claude code
- **사용자**: 1인 작성자가 Notion으로 쓴 글을 공개 웹에서 읽을 방문자 (작성자 본인은 웹 관리 화면을 사용하지 않음)

## 2. 고정 전제

- 글 작성, 수정, 삭제는 Notion에서만 한다. 웹에는 관리자 화면이 없다.
- 웹은 Notion API로 데이터를 **읽기만** 한다. 웹에서 Notion 데이터를 변경하지 않는다.
- 공개 웹이며 누구나 열람할 수 있다. 방문자 로그인은 없다.
- 데이터 저장용 별도 DB, 이미지 파일 저장소는 MVP에 두지 않는다. Notion이 원본이며, 서버 측 캐시만 사용한다.
- Notion 무료 요금제를 사용하므로 웹훅은 쓰지 않는다. 갱신은 시간 기반 재검증만 한다.
- 토이 프로젝트 규모(글 수십 건 이하)를 전제로 한다.

## 3. 사용자 여정

```
1. 피드 페이지 (진입점)
   ↓ 목록 로딩 (상태가 published인 글만, 발행일 최신순, 20개씩)
   ↓
   [글 0건] → 빈 상태 안내 표시 → 종료
   [글 있음] → 2번으로
   ↓
2. 피드 카드 클릭
   ↓
3. 글 상세 페이지
   ↓ 뒤로가기 또는 헤더의 "피드" 메뉴
4. 피드 페이지로 복귀 (직전 스크롤 위치와 로드된 목록 복원)

[목록 하단 도달] → 다음 20개 자동 로딩 (무한 스크롤)
[스크롤 일정 이상] → 하단 고정 "맨 위로" 버튼 표시
[글이 없는 주소로 진입 또는 비공개 글] → "글을 찾을 수 없음" 안내 → 피드 페이지 링크
```

### 4.1 MVP 핵심 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |

## 7. 데이터 모델

> 별도 DB 테이블은 만들지 않는다. 아래 두 항목은 Notion에서 읽어 서버에서 캐시하는 조회 모델이다.

### Notion 데이터베이스 속성 (MVP 최소 스키마)

Notion 속성명은 아래 이름을 기준으로 하며, 코드에서는 상수 한 곳에서만 매핑한다.

| Notion 속성명 | Notion 타입 | 용도 | 비고 |
|--------------|------------|------|------|
| `title` | 제목 (title) | 글 제목 | Notion 기본 제목 속성 |
| `published_at` | 날짜 (date) | 발행일, 정렬 기준 | 생성 시각이 아닌 전용 속성 |
| `status` | 선택 (select) | 공개 상태 | 값: `draft`, `published`, `archived` |
| `tags` | 다중 선택 (multi_select) | 태그 | 카드와 상세에 표시 |

- 커버 이미지는 Notion 페이지의 기본 커버를 사용한다 (별도 속성 없음).
- 요약은 속성을 두지 않고 본문에서 자동 추출한다 (7-1 참고).

### 글 (Post, Notion 페이지 기반)
| 필드 | 설명 | 타입/관계 |
|------|------|----------|
| id | Notion 페이지 ID | string |
| title | 제목 (`title`) | string |
| summary | 본문 앞부분 자동 추출 | string |
| published_at | 발행일 (`published_at`, 정렬 기준) | date |
| status | 공개 상태 (`status`), 피드·상세에는 `published`만 노출 | `draft` \| `published` \| `archived` |
| tags | 태그 목록 (`tags`) | string[] |
| cover_image | 커버 이미지 URL (Notion 발급 URL, 만료 시 placeholder) | string \| null |

#### 7-1. 요약 추출 규칙
- 본문의 텍스트 블록을 순서대로 이어 붙여 앞부분을 자른다.
- 기준: PC 카드 120자, 모바일 카드 80자 (CSS로 줄 수 제한과 병행).

### 글 블록 (PostBlock, 상세 렌더링용 캐시)
| 필드 | 설명 | 타입/관계 |
|------|------|----------|
| post_id | 소속 글 | → Post.id |
| type | 블록 종류 (지원 범위는 9장) | string |
| content | 블록 내용 (텍스트, 이미지 URL 등) | json |
| order | 본문 내 순서 | number |

## 9. 확정 사항

**글 상세 페이지**: MVP에 포함한다 (Q1).

**정렬 기준**: Notion의 `published_at` 날짜 속성, 내림차순 (Q2).

**공개 상태**: `status` 선택 속성 하나로 관리한다. 값은 `draft`(작성 중), `published`(공개), `archived`(보관)이며 `published`만 노출한다. `published`는 `public`보다 발행 흐름(초안 → 발행 → 보관)에 맞아 선택했다. 별도 `is_public` 속성은 두지 않는다 (Q3).

**갱신 방식** (Q4):
- 목록과 상세 페이지는 `revalidate: 300`(5분)으로 시간 기반 재검증한다.
- 웹훅은 사용하지 않는다 (Notion 무료 요금제에서 사용 불가).
- 응답 지연 허용치 (recommended): 캐시 적중 시 서버 응답 500ms 이하, 콘텐츠 반영 지연 최대 5분.

**이미지** (Q5):
- 이미지는 서버에 저장하지 않고 Notion이 발급한 URL을 그대로 사용한다.
- 재검증(5분)마다 새 URL을 받아오므로 만료는 드물다. 그래도 만료되거나 로딩에 실패하면 회색 배경 placeholder를 보여준다.
- 이미지 저장소 비용이 발생하지 않는다.

**목록 로딩** (Q6): 무한 스크롤, 1회 20개. 상세 이동 전 스크롤 위치와 로드된 개수를 sessionStorage에 저장하고, 복귀 시 복원한다. 스크롤이 일정 이상이면 하단에 "맨 위로" 플로팅 버튼을 표시한다.

**요약** (Q7): Notion 요약 속성 없이 본문 앞부분에서 자동 추출한다. PC 120자, 모바일 80자 (7-1 참고).

**태그** (Q8): 카드와 상세에 표시만 한다. 태그 클릭 필터는 MVP 이후로 미룬다.

**공개 범위** (Q9): 누구나 열람한다. 로그인, 비밀번호 기능은 없다.

**스키마** (Q10): 확정된 Notion DB가 없으므로 7장의 최소 스키마를 기준으로 DB를 만든다. 속성명은 `title`, `published_at`, `status`, `tags`이다.

**기존 스타터 페이지** (Q11): `about`, `dashboard`, `components/examples`는 삭제한다.

**사이트 기본 정보** (Q12):
- 사이트 이름: notion-blog
- 소개 문구: notion blog toy project with claude code
- 파비콘: Next.js 기본 파비콘 사용

**지원 블록 범위** (Q5): 아래 목록만 웹에서 렌더링한다. 그 외 블록은 "Notion에서 보기" 링크로 대체한다.
- 지원: 단락, 제목 1-3, 글머리·번호·체크 목록, 인용, 구분선, 코드 블록, 이미지, 표
- 대체 (Notion에서 보기 링크): 토글, 임베드(유튜브 등), 데이터베이스 인라인 블록 등 나머지 전부

- 기능 명세 F001~F008은 모두 페이지별 상세 기능의 "구현 기능" 목록에 있다.
